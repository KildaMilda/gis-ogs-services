# Техническое задание

## 1. Общие сведения
- **Название проекта:** Сервер публикации открытых геоданных по стандартам OGC (WMS и WFS) на базе GeoServer
- **Тема из каталога:** № 38 — «Публикация OGC-сервисов. WMS и WFS» (блок E)
- **Формат и исполнитель:** индивидуальная работа, Аверин Артём Артурович, группа 648

## 2. Цель проекта
Развернуть GeoServer, опубликовать на нём открытые векторные слои по выбранному городу по протоколам WMS и WFS и сделать простой веб-клиент для их просмотра и чтения атрибутов.

## 3. Для кого это нужно (пользователь результата)
Преподаватели и студенты ГИС-курсов, а также специалисты, которым удобно подключать актуальные слои карты по сети (в браузере или в QGIS), а не пересылать друг другу локальные файлы вручную.

## 4. Входные данные
- **Источник:** OpenStreetMap (открытая лицензия ODbL, с обязательным указанием источника).
- **Территория:** г. Рязань, Октябрьский район, микрорайон Дашково-Песочня.
- **Слои для базовой версии:** три векторных слоя с разными типами геометрии — здания (полигоны), дорожная сеть (линии) и остановки общественного транспорта (точки).
- **Формат и система координат:** файлы GeoPackage (`.gpkg`), предварительно очищенные в QGIS и приведённые к единой системе координат (WGS 84 / EPSG:4326 для хранения и EPSG:3857 для веб-отображения).

## 5. Ожидаемый результат
1. Локально разворачиваемый GeoServer с пошаговой инструкцией запуска в `README.md` и сохранёнными стилями слоёв.
2. Опубликованные слои, доступные по **WMS** (как готовые изображения карты) и по **WFS** (как векторные объекты с атрибутами в формате GeoJSON/GML).
3. Проверенные ответы сервиса: `GetCapabilities`, `GetMap` (WMS) и `GetFeature` (WFS).
4. Простая веб-страница на Leaflet (HTML + JS), которая подключается к серверу, накладывает слои на базовую карту и показывает свойства объекта по клику, плюс проверенное подключение того же сервиса в настольном QGIS.

## 6. Критерии готовности
1. GeoServer запускается с нуля по инструкции из `README.md` без ручных правок.
2. Запросы `GetCapabilities` по WMS и WFS возвращают валидный XML со списком всех опубликованных слоёв.
3. В веб-клиенте и в QGIS слои WMS ложатся на базовую подложку ровно, без смещения координат.
4. По запросу WFS приходят реальные векторные объекты, и клиент отображает их атрибуты (например, название объекта или тип дороги).
5. Оформлены паспорт данных, пояснительная записка и презентация для защиты.

## 7. Ограничения
- **Сроки:** рабочий прототип (MVP) к хакатону (~7 декабря), финальная доработка и сдача полного комплекта — до 12 декабря.
- **Объём данных:** берётся территория одного микрорайона и 3 лёгких векторных слоя (до 50 МБ), чтобы сервер работал быстро и без перегрузки памяти.
- **Оборудование и сеть:** сервер и клиент упаковываются в контейнеры для быстрого переноса; базовая разработка и резервный стенд для защиты работают локально, а при наличии ресурсов сервис дополнительно разворачивается на внешнем VPS (с доступом по сети).

## 8. Распределение работы
Проект выполняется в одиночку, поэтому все три части темы закрываются последовательно:
- **П1 (подготовка слоёв):** выгрузить данные из OSM, убрать лишнее в QGIS, проверить геометрию и СК, заполнить паспорт данных.
- **П2 (сервер и публикация):** развернуть GeoServer, настроить рабочее пространство и хранилища, опубликовать слои по WMS и WFS, задать базовые стили и проверить `GetCapabilities`.
- **П3 (клиент и документация):** собрать веб-карту на Leaflet, проверить подключение в QGIS, написать `README.md`, пояснительную записку и презентацию.
